# Database SQL-first

Schema runtime: [schema.prisma](schema.prisma).
Migration baseline canonical:
[migration.sql](migrations/202611120001_initial/migration.sql).
Seed placeholder: [seed.sql](seed.sql).

Berkas sekali salin-tempel dihasilkan dari migration + seed:
[setup.sql](../../../infra/supabase/setup.sql). Jangan edit bundle secara manual.
Jalankan pnpm db:bundle dari root bila sumber SQL berubah.

SQL memiliki CHECK, FK ke auth.users, FK deferred, trigger, RLS, grants, Storage dan
publication yang tidak seluruhnya dapat direpresentasikan Prisma. Client Prisma
memetakan tabel runtime; jangan memakai db push atau migration autogenerated untuk
menimpa SQL. auth.users dikelola Supabase, bukan model Prisma.

## Baseline Prisma setelah SQL manual

Setup aplikasi dilakukan SQL-first. Setelah setup.sql dijalankan pada project dev,
salin konfigurasi CLI lokal dengan DIRECT_URL owner yang memakai schema=app_private,
lalu jalankan dari root:

```sh
pnpm --filter @kantin/api db:validate
pnpm --filter @kantin/api db:generate
pnpm --filter @kantin/api exec prisma migrate resolve --applied 202611120001_initial
```

resolve hanya mencatat baseline yang SUDAH ada, bukan menjalankan migration ulang.
Jangan menjalankannya bila setup SQL belum berhasil. Metadata _prisma_migrations
ditempatkan di app_private oleh schema pada DIRECT_URL. Setelah metadata terbentuk,
jalankan sebagai operator di SQL Editor:

```sql
ALTER TABLE app_private._prisma_migrations ENABLE ROW LEVEL SECURITY;
ALTER TABLE app_private._prisma_migrations FORCE ROW LEVEL SECURITY;
REVOKE ALL ON app_private._prisma_migrations FROM PUBLIC, anon, authenticated, service_role, kantin_api, order_tracker;
```

Migration berikutnya harus direview sebagai SQL termasuk objek yang dikelola SQL.
Baseline ini sengaja menolak schema aplikasi yang sudah ada; bukan skrip reset.
Tidak ada perintah migrate/db push yang dijalankan terhadap Supabase oleh agen.
