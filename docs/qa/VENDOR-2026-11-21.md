# Validasi revisi vendor · 21 November 2026

**Status:** kode lokal dan pengujian otomatis; SQL live/deploy/UAT browser belum dilakukan. Rujukan keputusan/operasi: [vendor launch](../vendor-launch.md).

## Hasil implementasi

- Pelanggan memilih tenant pada beranda, lalu membuka menu `/tenant/:id`; tidak otomatis memilih tenant pertama. Nama/foto/harga/stok dari API. Halaman lokasi tidak lagi mengarang denah/jam atau posisi Warung Bu Sari.
- Tombol admin **Tambahkan katalog vendor** memasukkan Tens, Mie Ayam, Bento dan sembilan menu dengan harga tepat dari pengguna. Tenant draft, stok awal 0/Habis sesuai konfirmasi pengguna; foto/QRIS diisi operator. Import ulang tidak duplikat atau menimpa perubahan harga existing.
- Admin pertama memakai akun Auth aplikasi dan bootstrap operator, bukan signup admin publik. Tenant menerima undangan admin; akun pelanggan existing dapat dihubungkan secara eksplisit. Profil staf existing tidak diambil alih.
- Checkout persisten terikat akun, order per tenant, snapshot harga/QRIS, stok atomik dan replay terenkripsi/idempotent. Customer tidak dapat menyatakan paid; hanya mengirim klaim. Tenant/admin memeriksa pembayaran manual, lalu accept/reject/siap/selesai/batal unpaid. Pembatalan mengembalikan stok sekali, termasuk saat tenant diarsipkan.
- Order akun sendiri dan antrean staf dibaca melalui API. Kode subscription postgres_changes memakai Auth JWT; RLS hanya owner/staf aktif. Cursor feed melestarikan presisi timestamp. Banned/expired ditolak pada tes SQL; filter channel tidak dijadikan otorisasi.
- Panel menyediakan indikator/bunyi opt-in, tes/matikan bunyi dan izin desktop opsional. Baseline histori tidak berbunyi; id/version dideduplikasi. Polling fallback 5 detik; pelanggan memakai heartbeat 30 detik ketika channel terhubung. Tidak ada Web Push ketika browser ditutup.
- Tautan antarportal produksi tidak fallback localhost. API/Storage tetap server-only untuk mutasi; tidak menambah payment gateway, cash/card, chat atau aplikasi native.

## Bukti otomatis dan batasnya

- 22 tes kontrak shared (termasuk daftar/harga vendor, strict role input dan ledger notifikasi).
- 38 tes SQL dengan PGlite: 24 baseline, 5 pengelolaan, 9 ownership/order/inventory/bootstrap. Tes mencakup owner A/B dan tenant A/B, policy permissive tambahan tetap dibatasi restrictive policy, ban/expiry, rollback stok, cancel sekali dan snapshot.
- 16 tes HTTP/JWT/media/service: server Express lokal dengan DB/Auth/Storage doubles, termasuk import idempotent, linking staf, replay exact dengan owner/hash, rollback checkout dan AES-GCM tamper detection. Tidak mengklaim koneksi Prisma PostgreSQL/Supabase live dari doubles.
- Total 76 tes lulus pada pemeriksaan lokal; lint/typecheck/check-docs/check-design/Prisma validate dan bundle SQL juga diperiksa. Build produksi API dan kedua frontend diverifikasi setelah perubahan.
- Tidak ada account/email/payment/SQL/project live diubah, atau commit/push/deploy dilakukan. Kunci enkripsi tidak dicetak atau dirotasi otomatis oleh agen.
- Browser/Realtime WebSocket Supabase live, playback audio, izin desktop, HP dan alur email nyata belum diverifikasi. Izin origin browser pada percobaan sebelumnya ditolak; tidak dicoba melalui jalur lain. Harness Auth lama tetap terisolasi ke localhost dan tidak membuktikan checkout operasional baru.

## Langkah sebelum dipakai vendor

1. Operator menerapkan [orders-upgrade.sql](../../infra/supabase/orders-upgrade.sql) setelah management; jangan mengulang baseline pada DB existing. Migration menambah event INSERT/UPDATE pada publication dengan mempertahankan delete/truncate yang ada.
2. Siapkan admin aplikasi melalui [bootstrap](../../infra/supabase/bootstrap-admin.example.sql), runtime kantin_api, kunci replay persisten dan env API/frontend; allowlist dua origin serta redirect Auth yang tepat.
3. Login admin, import katalog vendor, isi foto/QRIS/stok, undang/link tenant, lalu aktifkan. Stok tetap 0 dan tenant tidak muncul publik sebelum setup selesai.
4. Push/deploy API dan kedua frontend, kemudian UAT dua pelanggan/dua tenant: pilih tenant, daftar/login, checkout retry, bayar/claim/reject/accept, stok, siap/selesai, cancel, notifikasi satu kali, muted/permission denied/reconnect/logout.

## Catatan fitur belum selesai

Denah asli dan pengunggahan denah, Web Push browser tertutup, expiry order otomatis,
refund, retensi/cleanup upload orphan, serta verifikasi operasional live tetap
belum selesai/tidak termasuk V1 sesuai batas masing-masing. Jangan menganggap
hasil tes lokal sebagai persetujuan produksi atau bukti uang telah diterima.
